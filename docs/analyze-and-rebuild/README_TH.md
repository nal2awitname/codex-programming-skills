# วิเคราะห์และสร้างโปรแกรมใหม่

**รุ่น 2.0:** เพิ่มเครื่องมือรันจริงสำหรับ inventory, evidence, readiness gate, builder handoff และ verification ดู [คู่มือรุ่น 2](V2_TH.md)

สกิล `analyze-and-rebuild` ใช้ทำความเข้าใจภาษา โครงสร้าง และพฤติกรรมของโปรแกรม แล้วเขียนโปรแกรมใหม่จากข้อกำหนดพฤติกรรม โดยห้ามคัดลอกโค้ดต้นฉบับ ห้ามแปลทีละบรรทัด และห้ามเปลี่ยนชื่อเพื่ออำพรางการคัดลอก

## เริ่มใช้งาน

แนบไฟล์หรือส่งลิงก์โปรแกรม แล้วเรียกสกิลที่ติดตั้งไว้:

```text
ใช้ $analyze-and-rebuild วิเคราะห์ภาษาและการทำงานของโปรแกรมนี้
แยกส่วนประกอบ อธิบายหลักการ แล้วสร้างใหม่จากข้อกำหนดพฤติกรรม
ห้ามคัดลอกโค้ดต้นฉบับ และจัดผลงานให้พัฒนาต่อใน GitHub ได้
ปลายทาง GitHub: <owner/repository ของโครงการ>
```

หากต้องการเฉพาะความเข้าใจ ให้ระบุว่า “วิเคราะห์อย่างเดียว ยังไม่ต้องสร้างใหม่” สกิลจะแยกสิ่งที่ตรวจพบ สิ่งที่อนุมาน และสิ่งที่ยังไม่ทราบ ไม่อ้างว่ารู้ประวัติการเขียนหรือส่วนที่เข้าถึงไม่ได้

การรองรับ EXE, APK, firmware หรือแพลตฟอร์มอื่นขึ้นอยู่กับไฟล์ เครื่องมือ และ runtime ที่เข้าถึงได้ การตรวจแบบ static ไม่เท่ากับทดสอบการทำงานจริง

## ผลงานที่ควรได้เมื่อสร้างโปรแกรมใหม่

- โค้ดใหม่ที่แยกตามหน้าที่ ใช้โครงสร้างตามภาษาหรือ framework ของโครงการ
- ข้อกำหนดพฤติกรรมและแผนผังส่วนประกอบ พร้อมระบุจุดที่ต้องแก้เมื่อเพิ่มฟีเจอร์
- ชุดทดสอบที่เขียนเอง คำสั่ง build/run/test และผลที่รันจริง
- บันทึกข้อมูลที่ผู้เขียนใหม่ได้รับ ระดับการแยกบริบท และส่วนที่ยังตรวจสอบไม่ได้
- ลิงก์ GitHub และสถานะจริงว่าอยู่ใน branch, pull request หรือ branch หลัก

ถ้าการส่งเข้า GitHub อยู่ในขอบเขตที่ผู้ใช้สั่งแล้ว สกิลจะดำเนินการต่อโดยไม่ถามอนุมัติซ้ำ หากยังระบุปลายทางไม่ได้ จะเตรียมไฟล์ให้ครบก่อนถามชื่อคลังที่ต้องการ

## การทดลองของรุ่นแรก

ขั้นตอนวิเคราะห์และเขียนใหม่เคยทดลองกับโปรแกรมคำนวณราคาแบบ Python JSON-lines โดยให้ผู้เขียนใหม่รับข้อกำหนดโดยไม่รับโค้ดต้นฉบับ ผลเทียบพฤติกรรมตรงกัน 203 กรณี และชุดทดสอบของโปรแกรมใหม่ผ่าน 10 การทดสอบ ตัวอย่างนี้ใช้ตรวจขั้นตอนของสกิล ไม่ใช่หลักฐานว่ารองรับทุกโปรแกรมหรือทุกแพลตฟอร์ม

ดูขั้นตอนแก้ไขและตรวจรับการเปลี่ยนแปลงใน [DEVELOPMENT.md](DEVELOPMENT.md)
