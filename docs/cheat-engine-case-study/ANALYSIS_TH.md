# ทดลองสกิลกับ Cheat Engine: ค้นหาค่าตัวเลข

ทดลองกระบวนการวิเคราะห์และเขียนใหม่ในขอบเขตเล็ก: สแกนจำนวนเต็ม 4 ไบต์แล้วกรองผลซ้ำ สร้างโปรแกรมใหม่ชื่อ **Value Scan Lab** โดยผู้เขียนได้รับเฉพาะข้อกำหนดที่ตรวจแล้ว ไม่มีโค้ดต้นฉบับของ Cheat Engine

**ยังไม่ได้รัน Cheat Engine ตัวจริงหรือวัดผลเทียบกับ binary ของมัน** การทำงานที่เลือกอ้างอิงเอกสารทางการ ผลทดสอบโปรแกรมใหม่จึงเป็นการตรวจข้อกำหนด ไม่ใช่หลักฐานว่าทำงานเหมือน Cheat Engine ทุกกรณี

## สิ่งที่สร้างขึ้นใหม่

ตัวอย่างใช้บัฟเฟอร์หน่วยความจำของโปรแกรมตัวเอง เก็บจำนวนเต็ม signed 32-bit และรายงานตำแหน่งเป็น byte offset ภายในบัฟเฟอร์ ภาษา สถาปัตยกรรม หน้าต่าง CLI การตรวจ input และข้อมูลตัวอย่างเป็นการออกแบบใหม่ของห้องทดลอง ไม่อ้างว่าเป็น interface ของ Cheat Engine

| ขั้นตอนตัวอย่าง | ผลที่กำหนดและตรวจในโปรแกรมใหม่ |
| --- | --- |
| ข้อมูลเริ่ม `[137,20,137,-3,137,0]` แล้วค้นหา 137 | พบ 3 จุด: offsets 0, 8, 16 |
| ลดค่าตัวอย่างที่ slot 2 จาก 137 เป็น 120 แล้วกรองค่า 120 | เหลือ offset 8 เพียงจุดเดียว |
| เริ่มแบบไม่ทราบค่า แล้วเปลี่ยนค่าและเลือก changed/unchanged/increased/decreased | คัดกรองจากผลรอบก่อนตามคุณสมบัติที่ระบุไว้ |
| เริ่มค้นใหม่/ล้างสถานะ หรือป้อนข้อมูลผิดชนิด/เกิน int32 | ตรวจตามกติกาใหม่ที่ระบุใน contract |

ข้อกำหนดมี 9 ข้อและกรณีทดสอบสังเคราะห์ 22 กรณี ทุกกรณีติดป้ายเป็น proposed acceptance checks ไม่สร้าง observation ปลอมว่ารัน Cheat Engine มาแล้ว ตัวเลขตัวอย่างและผลที่คาดหวังสร้างขึ้นเองจากคุณสมบัติที่กำหนด

## การทดสอบและการแยกข้อมูล

โปรแกรมใหม่มี CLI สำหรับ demo/scenario, GUI Tkinter และชุดทดสอบ acceptance/state/type/CLI/GUI คำสั่งและผลที่รันในเครื่องผู้สร้างอยู่ใน [คู่มือโปรแกรม](../../examples/value-scan-lab/README_TH.md)

[GitHub Actions](https://github.com/nal2awitname/codex-programming-skills/actions/workflows/value-scan-lab.yml) รันทดสอบบน Windows/Linux กับ Python 3.10/3.12 โดย Windows ตั้ง `VALUE_SCAN_REQUIRE_GUI=1`: ถ้าสร้างหน้าต่างไม่ได้ต้องล้มเหลวแทนการข้าม จึงแยกการทดสอบ desktop จริงออกจากการตรวจ CLI ส่วนเครื่อง Linux ที่ไม่มีจอจะรายงาน GUI ว่าข้ามตามจริง ตรวจผลของ commit ที่ต้องการใช้งานจาก workflow นี้

ผู้วิเคราะห์อ่านเฉพาะเอกสารและ metadata แล้วส่งให้บริบทผู้เขียนใหม่เฉพาะ contract ที่ตรวจเนื้อหาทั้งหมด ผู้เขียนไม่ได้รับ implementation หรือรายงานต้นฉบับ มี filesystem ร่วมกันและไม่มีการบังคับสิทธิ์ห้ามเข้าถึงต้นฉบับ จึงเป็นการแยกข้อมูล/บริบทตามคำสั่ง ไม่ใช่หลักฐานรับรองว่าเป็นห้องปลอดต้นฉบับที่บังคับด้วยระบบ

## ผลต่อการพัฒนาสกิล

การทดลองพบว่าตัวตรวจอัตโนมัติเดิมยังไม่มี Pascal/Lazarus จึงเพิ่มในรุ่น **2.0.1**:

- ตรวจตัวบ่งชี้ไวยากรณ์ Pascal ใน `.pas`, `.pp`, `.lpr`, `.dpr` โดยไม่ส่งออกเนื้อหาโค้ด
- อ่าน compiler modes จาก XML `.lpi` ที่สมบูรณ์ และรายงานเป็นข้อบ่งชี้ราย component
- ไม่ยืนยันภาษาเมื่อเป็น XML ผิดรูป ถูกตัด ข้อมูลไม่เกี่ยวข้อง หรือมี mode ที่ไม่รู้จัก
- เพิ่มกรณีทดสอบที่เขียนเอง ไม่ใช้ source/fixture ของ Cheat Engine

ยังไม่ครอบคลุมการสแกนทุกโปรเซส การป้องกันหน่วยความจำ ความเท่ากันกับ binary ต้นฉบับ ไดรเวอร์ debugger pointer scan freezing speed controls หรือการสร้าง Cheat Engine ครบทั้งโปรแกรม
