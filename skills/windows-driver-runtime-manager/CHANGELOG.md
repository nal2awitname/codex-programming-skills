# Changelog

## 1.2.0 — 2026-11-11

แก้ข้อบกพร่องที่เปิดอยู่ทั้งหมดจาก 1.1.0 (DRM-101 ถึง DRM-119) และที่พบเพิ่มระหว่างแก้ (DRM-120 ถึง DRM-124, DRM-127)
ส่วนที่ต้องใช้ฮาร์ดแวร์จริงยืนยันตาม [references/manual-test-checklist.md](references/manual-test-checklist.md)

### เพิ่ม
- ซ่อนไดรเวอร์ที่ไม่ต้องการจาก Windows Update (คลิกขวาในตารางอัปเดต) และใช้เซิร์ฟเวอร์ขององค์กร (WSUS) เมื่อค้นออนไลน์ไม่ได้
- รายงานหลังติดตั้งมีตาราง "ไดรเวอร์ที่เปลี่ยนแปลงหลังติดตั้ง" (อัปเดต/แก้ปัญหาแล้ว/เกิดปัญหาใหม่/พบใหม่)
- ไฟล์บีบอัดที่มีรหัสผ่าน (ใส่ในช่องตัวเลือก ไม่ลง log) และแบบแยกหลายไฟล์ `.001` / `.part1.rar`
- เลือก HP Image Assistant ตามรายการรุ่นที่ HP รองรับ (`platformList.cab`) แทนการเดาจากชื่อรุ่น
- .NET Desktop Runtime ตรวจ SHA512 จาก `releases.json` ของ Microsoft ก่อนติดตั้ง
- แคชระดับการรับรองไดรเวอร์ (`cert-cache.json`) สแกนรอบถัดไปเร็วขึ้น
- ลอง `winget source update` อัตโนมัติเมื่อ winget ล้มเหลวเพราะแหล่งข้อมูล
- ชุดดีบักเก็บ log ของ Dell Command | Update และ Lenovo System Update ด้วย
- คำแนะนำเมื่อรันในคอนโซลแบบเก่าที่แสดงภาษาไทยไม่ได้
- CI: PSScriptAnalyzer, ทดสอบทำต่อหลังรีสตาร์ทครบวงจร, ไฟล์ตัวอย่างรายงาน Dell/HP และ releases.json; รายการทดสอบด้วยมือ

### แก้ไข
- ความหมาย exit code ของ Dell Command | Update (4 = ไม่ใช่ Admin, 5 = รีสตาร์ทค้าง, 7 = ไม่รองรับรุ่น) และ HP Image Assistant (3020 = บาง SoftPaq ล้มเหลว, 257 = ไม่มีรายการ) ตามเอกสารของผู้ผลิต
- เครื่องมือ OEM ที่ไม่รองรับรุ่นนั้นได้สถานะ "ทำต่อเอง" พร้อมเปิดหน้า Support แทน "ล้มเหลว"
- Game Mode และรายการโปรแกรมแบบต่อผู้ใช้ใช้โปรไฟล์ของผู้ใช้ที่ล็อกอิน ไม่ใช่บัญชี Admin ที่ใช้ยกระดับสิทธิ์
- Lenovo System Update ไม่ค้างที่หน้าข้อตกลง, Windows Server ข้ามจุดคืนค่าพร้อมเหตุผล, InstallShield แบบเงียบหมดเวลาใน 20 นาทีพร้อมวิธีแก้
- ทำต่อหลังรีสตาร์ทเมื่อเปิดจาก .ps1 โดยตรงและเมื่อใช้ `-Root` อื่น
- ฟังก์ชันที่คืนรายการส่งออกทาง pipeline ตามปกติ (เลิกใช้ `return , $array` ที่ทำให้เกิดบั๊กซ้ำ)
- การค้นหา Windows Update มีเวลาหมดและหยุดได้ และโหมดทดลองไม่ค้นหาออนไลน์ใหม่ (ต้นเหตุที่ CI บน PowerShell 7 ค้าง — DRM-127)

## 1.1.0 — 2026-11-10

### เพิ่ม
- ฐานข้อมูลรหัสข้อผิดพลาด `scripts/errors.json` (MSI, Windows Update, WUSA, DISM, pnputil, winget, MSIX, Dell Command | Update, HP Image Assistant และรหัสปัญหาของอุปกรณ์) — ทุกรายการที่ล้มเหลวมีความหมายภาษาไทยและวิธีแก้ใน log หน้าต่าง และรายงาน
- โหมด `-Mode Diagnose` และปุ่ม "รวบรวมข้อมูลดีบัก (zip)": สรุประบบ อุปกรณ์ที่มีปัญหา log ผลลัพธ์คำสั่งที่ล้มเหลว รายงานดิบของ OEM setupapi.dev.log Event Log และ Driver Store โดยซ่อนชื่อเครื่อง ชื่อผู้ใช้ และ Serial
- เก็บผลลัพธ์เต็มของคำสั่งที่ล้มเหลวเป็น `Logs\Output_*.txt`
- ค้นหาไดรเวอร์ที่ Microsoft รับรองใน Microsoft Update Catalog จาก Hardware ID (คลิกขวาที่อุปกรณ์ และลิงก์ในรายงาน) พร้อมคอลัมน์ "วิธีแก้"
- บันทึก/โหลดชุดที่เลือก (`-SelectionProfile`, `-ExportProfile`, ปุ่มในหน้าต่าง) เพื่อใช้ซ้ำกับหลายเครื่อง
- ตรวจไดรเวอร์ผู้ผลิตที่เก่ากว่า 3 ปีในตารางความเข้ากันได้
- แสดงเวอร์ชันในหน้าต่าง log และรายงาน (`Get-DrmVersion`)
- CI: ทดสอบชุดดีบัก (ต้องไม่มีชื่อเครื่องหลุด), ตัวเปิดจากโฟลเดอร์ที่มีวงเล็บ, ติดตั้งรอบสองต้องไม่ติดตั้งซ้ำ, smoke test ของหน้าต่างครอบคลุมชุดที่เลือกและชุดดีบัก

### แก้ไข
- DRM-009 ถึง DRM-020 (การส่งพารามิเตอร์ตอนขอสิทธิ์ Admin, หน้าต่างคอนโซล, ตัวเปิด .cmd, VC++ 2010 ติดตั้งซ้ำ, `-Items`, เปิดเบราว์เซอร์ในโหมดคำสั่ง, การเลือกหายเมื่อสแกนซ้ำ, ข้อมูลข้อผิดพลาดไม่พอ, เปิดซ้อนหลายหน้าต่าง, ขั้น CI ที่ไม่เคยตรวจจริง)
- เปิดรายงานและลิงก์ผ่าน explorer.exe เพื่อไม่ให้เบราว์เซอร์ทำงานด้วยสิทธิ์ Administrator
