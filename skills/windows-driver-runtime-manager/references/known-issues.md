# บันทึกข้อบกพร่องและแผนแก้ไข (Debug log)

อ่านไฟล์นี้ก่อนแก้บั๊กหรือพัฒนารอบถัดไป เลือกรายการตามลำดับความสำคัญ ทำซ้ำอาการตามขั้นตอน แก้ แล้วย้ายไปตาราง
"แก้แล้ว" พร้อมระบุรุ่นและวิธีตรวจ อย่าลบประวัติ — ใช้เป็นหลักฐานว่าเคยพบอะไรและป้องกันไม่ให้กลับมาอีก

อัปเดตล่าสุด: 2026-11-11 (v1.2.0) · ระดับ: **สูง** = ทำงานผิด/ข้อมูลผิดในสถานการณ์ปกติ, **กลาง** = มีทางเลี่ยงหรือเกิดบางเครื่อง, **ต่ำ** = ความสะดวก/ความเสี่ยงต่ำ

## วิธีเก็บข้อมูลดีบัก

1. ให้ผู้ใช้กด **แท็บ 6 > รวบรวมข้อมูลดีบัก (zip)** หรือรัน `DriverRuntimeManager.ps1 -Mode Diagnose -SinceHours 48`
   ได้ไฟล์ `%ProgramData%\DriverRuntimeManager\Reports\DRM_Diagnostics_<เวลา>.zip` ที่ซ่อนชื่อเครื่อง ชื่อผู้ใช้ และ Serial แล้ว
   (ใส่ `-IncludeIdentifiers` เมื่อต้องการ Serial/Service Tag เพื่อค้นไดรเวอร์ของ OEM)
2. ในไฟล์ zip: `summary.txt` (ระบบ winget proxy), `devices-problem.txt` (Hardware ID + วิธีแก้ + ลิงก์ Update Catalog),
   `logs_DRM_*.log` (log หลัก), `logs_Output_*.txt` (ผลลัพธ์เต็มของคำสั่งที่ล้มเหลว), `oem_*` (รายงานดิบของ Dell/HP),
   `oemlog_*` (log ของ Dell Command | Update / Lenovo System Update เอง), `setupapi-dev-tail.log`,
   `events-*.txt` (Kernel-PnP, DeviceSetupManager, WindowsUpdateClient, MsiInstaller, ข้อผิดพลาดระบบ), `pnputil-enum-drivers.txt`
3. ทุกรายการที่ล้มเหลวมี "คำแนะนำ" จาก `scripts/errors.json` ใน log, หน้าต่าง และรายงาน — ถ้าเจอรหัสที่ยังไม่รู้จัก ให้เพิ่มลง `errors.json` (ระบุ `sources` ถ้าความหมายขึ้นกับเครื่องมือ)
4. ใน log หลักค้นหา `[ERROR]`, `[WARN ]`, `คำแนะนำ:` และ `บันทึกผลลัพธ์เต็มของคำสั่ง`
5. ไฟล์ข้อมูลของโปรแกรมใน `%ProgramData%\DriverRuntimeManager`: `cert-cache.json` (แคชระดับการรับรอง ลบได้เสมอ — จะตรวจใหม่),
   `hpia-platformList.xml` (รายการรุ่นที่ HP Image Assistant รองรับ อายุ 7 วัน), `resume.json` (งานที่ค้างรอทำต่อหลังรีสตาร์ท)

## กับดักของ PowerShell ที่พบในโครงการนี้

- ไฟล์ .ps1/.psm1 ที่มีภาษาไทยต้องเป็น UTF-8 **มี BOM** ไม่งั้น Windows PowerShell 5.1 อ่านเป็น ANSI แล้วแยกวิเคราะห์ไม่ได้
- ตั้งแต่ 1.2 ฟังก์ชันคืนรายการทาง pipeline: ผู้เรียกครอบ `@(...)` ทุกครั้ง เพราะว่างจะได้ `$null` และหนึ่งรายการจะได้ออบเจกต์เดี่ยว
  (`([pscustomobject]@{}).Count` เป็น `$null` ใน Windows PowerShell 5.1)
- `$x = if (...) { @(...) } else { @() }` ก็ถูกแตกเหมือน pipeline — เขียน `$x = @(if (...) { ... })`
- เลขฐานสิบหกอย่าง `0xFFFF0000` เป็น Int32 ติดลบ — ใช้ `0xFFFF0000L` และเก็บรหัสเป็น int64
- `@($ht[$int64Key])` โยน "Argument types do not match" — ใช้คีย์ข้อความ
- Linux/macOS ตัด exit code เหลือ 0–255 (1603 → 67, 3010 → 194) — การทดสอบข้ามแพลตฟอร์มต้องคำนึงถึง
- `powershell -File` ส่งค่าอาร์เรย์มาเป็นข้อความเดียว — แยก `-Items` ด้วย `,` และ `-Files` ด้วย `;`
- เครื่องไทยใช้ปฏิทินพุทธ — จัดรูปแบบวันที่ด้วย `InvariantCulture` เสมอ
- `.cmd` ต้องเป็น ASCII + CRLF และห้าม `pause` ในงานอัตโนมัติ
- อย่าตั้งชื่อตัวแปร/พารามิเตอร์ `$args`, `$input`, `$PROFILE`, `$sender`, `$IsWindows` (ตัวแปรอัตโนมัติ — `$IsWindows` มีใน PowerShell 7)
- `Set-ItemProperty -Type` เป็นพารามิเตอร์ของ registry provider เท่านั้น — เขียนรีจิสทรีผ่าน `Set-DrmRegistryValue` เพื่อ mock ใน Pester ได้ทุกแพลตฟอร์ม
- Pester: ฟังก์ชันที่ถูกเรียกจากในโมดูลต้อง mock ด้วย `-ModuleName DriverRuntimeManager`
- `-eq`/`-in` ไม่สนตัวพิมพ์ — ตั้งใจใช้กับ System ID ของ HP และชื่อแอตทริบิวต์ XML
- ฟังก์ชันที่คืนรายการห้าม `return $null` เมื่อล้มเหลว — `@($null).Count` เป็น 1 ทำให้ซ่อนข้อผิดพลาดจริง (พบใน CI ระหว่างแก้ DRM-119) ให้ `return` เปล่า
- `expand.exe <cab> -F:* <dir>` ไม่ยอมแตกลงโฟลเดอร์เดียวกับไฟล์ .cab ("Cannot expand a file onto itself") — แตกลงโฟลเดอร์ย่อยเสมอ

## สิ่งที่ยังไม่ได้ทดสอบบนเครื่องจริง

CI ทดสอบบน GitHub Actions (Windows Server 2025 VM, PowerShell 5.1 และ 7) และ Linux: Pester (รวมทำต่อหลังรีสตาร์ทแบบไม่รีสตาร์ทจริง),
PSScriptAnalyzer, SelfTest, หน้าต่างจริงแบบอัตโนมัติ, สแกน + Windows Update, ทดลองติดตั้งทุกรายการ, ติดตั้งจริง VC++/.NET (ตรวจ SHA512)/DirectX/WebView2
และรอบสองต้องไม่ติดตั้งซ้ำ, ชุดดีบัก, ตัวเปิด .cmd, เขียน/ลบ RunOnce
**ยังไม่ครอบคลุม:** ดูตาราง "สถานะปัจจุบัน" ด้านบน และการติดตั้งไดรเวอร์จาก Windows Update จริง (VM ไม่มีรายการเสนอ), pnputil กับแพ็กเกจไดรเวอร์จริง

## แผนรอบถัดไป (เรียงตามความสำคัญ)

1. ยืนยันรายการในตาราง "สถานะปัจจุบัน" บนเครื่องจริงตาม [manual-test-checklist.md](manual-test-checklist.md) แล้วเพิ่มรายงานดิบจริงเป็น fixture
2. DRM-125: เก็บ snapshot อุปกรณ์แบบย่อ (DeviceId, เวอร์ชัน, INF, รหัสปัญหา) ลง resume.json เพื่อให้รายงานหลังรีสตาร์ทเทียบได้
3. DRM-126: ปุ่มเลิกซ่อนไดรเวอร์ Windows Update ในหน้าต่าง
4. ฟีเจอร์: ตรวจอัปเดตอัตโนมัติรายสัปดาห์ (Task Scheduler), ดาวน์โหลดเก็บไว้ติดตั้งแบบออฟไลน์
