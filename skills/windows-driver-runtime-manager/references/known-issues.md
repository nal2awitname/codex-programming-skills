# บันทึกข้อบกพร่องและแผนแก้ไข (Debug log)

อ่านไฟล์นี้ก่อนแก้บั๊กหรือพัฒนารอบถัดไป เลือกรายการที่ "เปิดอยู่" ตามลำดับความสำคัญ ทำซ้ำอาการตามขั้นตอน แก้ แล้วย้ายไปตาราง
"แก้แล้ว" พร้อมระบุรุ่นและวิธีตรวจ อย่าลบประวัติ — ใช้เป็นหลักฐานว่าเคยพบอะไรและป้องกันไม่ให้กลับมาอีก

อัปเดตล่าสุด: 2026-11-10 (v1.1.0) · ระดับ: **สูง** = ทำงานผิด/ข้อมูลผิดในสถานการณ์ปกติ, **กลาง** = มีทางเลี่ยงหรือเกิดบางเครื่อง, **ต่ำ** = ความสะดวก/ความเสี่ยงต่ำ

## วิธีเก็บข้อมูลดีบัก

1. ให้ผู้ใช้กด **แท็บ 6 > รวบรวมข้อมูลดีบัก (zip)** หรือรัน `DriverRuntimeManager.ps1 -Mode Diagnose -SinceHours 48`
   ได้ไฟล์ `%ProgramData%\DriverRuntimeManager\Reports\DRM_Diagnostics_<เวลา>.zip` ที่ซ่อนชื่อเครื่อง ชื่อผู้ใช้ และ Serial แล้ว
   (ใส่ `-IncludeIdentifiers` เมื่อต้องการ Serial/Service Tag เพื่อค้นไดรเวอร์ของ OEM)
2. ในไฟล์ zip: `summary.txt` (ระบบ winget proxy), `devices-problem.txt` (Hardware ID + วิธีแก้ + ลิงก์ Update Catalog),
   `logs_DRM_*.log` (log หลัก), `logs_Output_*.txt` (ผลลัพธ์เต็มของคำสั่งที่ล้มเหลว), `oem_*` (รายงานดิบของ Dell/HP),
   `setupapi-dev-tail.log`, `events-*.txt` (Kernel-PnP, DeviceSetupManager, WindowsUpdateClient, MsiInstaller, ข้อผิดพลาดระบบ), `pnputil-enum-drivers.txt`
3. ทุกรายการที่ล้มเหลวมี "คำแนะนำ" จาก `scripts/errors.json` ใน log, หน้าต่าง และรายงาน — ถ้าเจอรหัสที่ยังไม่รู้จัก ให้เพิ่มลง `errors.json` (ระบุ `sources` ถ้าความหมายขึ้นกับเครื่องมือ)
4. ใน log หลักค้นหา `[ERROR]`, `[WARN ]`, `คำแนะนำ:` และ `บันทึกผลลัพธ์เต็มของคำสั่ง`

### DRM-101 อ่านผลสแกนของ Dell/HP (สูง)
- **อาการ:** ปุ่มตรวจหาอัปเดตบนเครื่อง Dell/HP อาจขึ้น "พบ 0 รายการ" ทั้งที่โปรแกรมของผู้ผลิตแสดงว่ามีอัปเดต (การติดตั้งจริงไม่กระทบ เพราะสั่งเครื่องมือผู้ผลิตติดตั้งทั้งหมด)
- **ทำซ้ำ:** เครื่อง Dell Latitude/OptiPlex หรือ HP EliteBook ที่มีอัปเดตค้าง → `-Mode Scan -CheckUpdates` → เทียบรายการใน log กับหน้าต่าง Dell Command | Update / HP Image Assistant
- **สาเหตุที่สงสัย:** `Read-DrmOemReport` เดาโครงสร้าง (`//update` → name/version/category ของ Dell และ `HPIA.Recommendations` ของ HP) จากเอกสารและตัวอย่างชุมชน
- **แผน:** ขอไฟล์ `oem_*.xml/json` จากชุดข้อมูลดีบักของเครื่องจริงอย่างน้อยยี่ห้อละ 1 เครื่อง → เขียน Pester จากไฟล์ตัวอย่าง (ลบ Serial ก่อน) → ปรับตัวอ่าน
- **ตรวจรับ:** จำนวนและชื่อรายการตรงกับหน้าต่างของผู้ผลิต

### DRM-102 รีสตาร์ทแล้วทำต่อ (สูง)
- **อาการที่เป็นไปได้:** หลังติดตั้ง BIOS/ชิปเซ็ตที่คืน 3010 เครื่องรีสตาร์ทแล้วไม่ทำต่อ หรือทำซ้ำรายการเดิม
- **ทำซ้ำ:** VM Windows 11 → แท็บติดตั้งจากไฟล์เพิ่ม EXE ทดสอบที่ตั้งชื่อ `BIOS_test.exe` และคืน 3010 (ลำดับ 10) + รันไทม์ 1 รายการ → ติดตั้ง → ดู `%ProgramData%\DriverRuntimeManager\resume.json` และ `HKLM\...\RunOnce\DriverRuntimeManagerResume` → ล็อกอินใหม่
- **ต้องยืนยัน:** RunOnce เรียก `.cmd -Resume` ได้, UAC ขึ้นหลังล็อกอิน, ทำต่อเฉพาะรายการที่เหลือ, ลบ resume.json เมื่อเสร็จ, ไม่วนเกิน 3 รอบ
- **แผน:** เพิ่ม CI ทดสอบ `Save-DrmResumeState`/`Read-DrmResumeState` แบบไม่รีสตาร์ท และคู่มือทดสอบด้วยมือบน VM

### DRM-103 จุดคืนค่าระบบ (กลาง)
- CI เป็น Windows Server ซึ่งไม่มีคลาส WMI `SystemRestore` จึงข้ามไป (บันทึกเตือน) ต้องทดสอบบน Windows 10/11 ว่าสร้างได้, เปิด System Protection ให้เมื่อปิดอยู่, และคืนค่า `SystemRestorePointCreationFrequency` เดิม

### DRM-104 Lenovo System Update (กลาง)
- `tvsu.exe /CM` อาจแสดงหน้าต่างข้อตกลงครั้งแรก และ exit code ไม่มีเอกสารชัดเจน ปัจจุบันถือ 0 = สำเร็จ แล้วรอโปรเซส `Tvsukernel` จบ
- **แผน:** ทดสอบบน ThinkPad จริง เก็บ log ของ System Update (`%ProgramData%\Lenovo\SystemUpdate\logs`) เพิ่มเข้าชุดดีบัก แล้วกำหนด exit code ในแคตตาล็อก

### DRM-105 Dell Command | Update บนรุ่นที่ไม่รองรับ (กลาง)
- รหัส 4 ถูกแปลเป็นคำแนะนำ "ใช้ SupportAssist" แล้ว แต่สถานะยังเป็น "ล้มเหลว" **แผน:** ถ้า DCU คืน 4 ให้เปิดหน้า Dell Support (เฉพาะ GUI) และตั้งสถานะ "ทำต่อเอง"

### DRM-106 ความเร็วการสแกน (กลาง)
- `Get-DrmDriverPackages` เรียก `Get-AuthenticodeSignature` กับทุก .cat (เครื่องที่มี 200+ แพ็กเกจใช้ 10–40 วินาที)
- **แผน:** แคชระดับการรับรองไว้ใน `%ProgramData%\DriverRuntimeManager\cert-cache.json` โดยใช้ path + เวลาแก้ไขของ .cat เป็นคีย์ **ตรวจรับ:** สแกนรอบที่สองเร็วขึ้น และผลเท่าเดิม

### DRM-107 ความถูกต้องของไฟล์ .NET (กลาง)
- **แผน:** อ่าน `releases.json` ของแต่ละช่อง (ประมาณ 1 MB) เฉพาะตอนติดตั้ง เพื่อเอาเวอร์ชัน windowsdesktop ที่แท้จริงและ SHA512 แล้วส่งให้ `Save-DrmDownload -Sha512`

### DRM-108 แหล่งข้อมูล winget (กลาง)
- **แผน:** เมื่อ winget ล้มเหลวด้วยรหัสกลุ่มแหล่งข้อมูล (ตรวจด้วย `winget error`) ให้รัน `winget source update` หนึ่งครั้งแล้วลองใหม่ บันทึกทั้งสองรอบ

### DRM-109 Game Mode กับ HKCU (ต่ำ)
- ถ้าผู้ใช้มาตรฐานยกระดับสิทธิ์ด้วยบัญชี Admin อื่น การตั้งค่าจะไปอยู่ในโปรไฟล์ของบัญชี Admin **แผน:** หา SID ของผู้ใช้ที่ล็อกอิน (เจ้าของ explorer.exe) แล้วเขียน `HKU\<SID>\...`

### DRM-110 ภาษาไทยในคอนโซลเก่า (ต่ำ)
- log และรายงานถูกต้องเสมอ ปัญหาอยู่ที่ฟอนต์ของ conhost **ทางเลี่ยง:** ใช้ Windows Terminal หรือดูผลใน log/รายงาน **แผน:** แสดงคำแนะนำนี้เมื่อรันโหมดคำสั่งใน conhost

### DRM-112 ข้อตกลงการคืนค่าอาร์เรย์ (ต่ำ — ออกแบบ)
- ฟังก์ชันที่คืนรายการใช้ `return , $list` → ถ้าครอบด้วย `@()` จะได้อาร์เรย์ซ้อน และถ้า pipe ตรง ๆ ตัวกรองจะเห็นทั้งอาร์เรย์เป็นออบเจกต์เดียว ทำให้เกิด DRM-002, DRM-019 และบั๊กในชุดทดสอบ 2 ครั้ง
- **แผน v1.2:** เปลี่ยนเป็นส่งออกทาง pipeline ตามปกติ แล้วให้ผู้เรียกใช้ `@(...)` ทุกจุด พร้อมเพิ่มกฎ PSScriptAnalyzer (DRM-113) และทดสอบทุกฟังก์ชันกรณีว่าง/หนึ่งรายการ/หลายรายการ

### DRM-113–119
- **113:** เพิ่ม `Invoke-ScriptAnalyzer -Settings PSGallery` ใน CI (ยกเว้น `PSAvoidUsingWriteHost` ในโหมดคำสั่ง)
- **114:** เพิ่มคำสั่ง "ซ่อนอัปเดตนี้" (`IUpdate.IsHidden = $true`) ในเมนูคลิกขวาของรายการ Windows Update
- **115:** ตั้งเวลาหมดสั้นลง (เช่น 20 นาที) สำหรับ InstallShield ที่ไม่มีไฟล์ตอบ และเตือนให้ล้างช่องตัวเลือกเพื่อเปิดหน้าต่างผู้ผลิต
- **116:** ส่งรหัสผ่านให้ 7-Zip ผ่านกล่องข้อความ และรวมไฟล์ `.001/.part1.rar` อัตโนมัติ
- **117:** ทดสอบด้วยมือที่ 100/150/200% และลากไฟล์จาก Explorer; พิจารณา UI Automation ใน CI
- **118:** ตั้งใจให้รอเพื่อไม่ให้ไดรเวอร์ติดตั้งครึ่งเดียว — แสดงข้อความ "กำลังรอ Windows Update ติดตั้งให้จบ" ให้ชัดขึ้น
- **119:** เพิ่มการตรวจด้วย `Win32_ComputerSystem.SystemFamily` และรายการรุ่นที่ HPIA รองรับ

## กับดักของ PowerShell ที่พบในโครงการนี้

- ไฟล์ .ps1/.psm1 ที่มีภาษาไทยต้องเป็น UTF-8 **มี BOM** ไม่งั้น Windows PowerShell 5.1 อ่านเป็น ANSI แล้วแยกวิเคราะห์ไม่ได้
- `return , $list` คืนอาร์เรย์เป็นออบเจกต์เดียว: เก็บใส่ตัวแปรก่อน pipe และห้ามครอบด้วย `@()` (DRM-112)
- เลขฐานสิบหกอย่าง `0xFFFF0000` เป็น Int32 ติดลบ — ใช้ `0xFFFF0000L` และเก็บรหัสเป็น int64
- `@($ht[$int64Key])` โยน "Argument types do not match" — ใช้คีย์ข้อความ
- Linux/macOS ตัด exit code เหลือ 0–255 (1603 → 67) — การทดสอบข้ามแพลตฟอร์มต้องคำนึงถึง
- `powershell -File` ส่งค่าอาร์เรย์มาเป็นข้อความเดียว — แยก `-Items` ด้วย `,` และ `-Files` ด้วย `;`
- เครื่องไทยใช้ปฏิทินพุทธ — จัดรูปแบบวันที่ด้วย `InvariantCulture` เสมอ
- `.cmd` ต้องเป็น ASCII + CRLF และห้าม `pause` ในงานอัตโนมัติ
- อย่าตั้งชื่อตัวแปร/พารามิเตอร์ `$args`, `$input`, `$PROFILE` (ตัวแปรอัตโนมัติ)

## สิ่งที่ยังไม่ได้ทดสอบบนเครื่องจริง

CI ทดสอบบน GitHub Actions (Windows Server 2025 VM, PowerShell 5.1 และ 7) และ Linux: Pester, SelfTest, หน้าต่างจริงแบบอัตโนมัติ,
สแกน + Windows Update, ทดลองติดตั้งทุกรายการ, ติดตั้งจริง VC++/.NET/DirectX/WebView2 และรอบสองต้องไม่ติดตั้งซ้ำ, ชุดดีบัก, ตัวเปิด .cmd
**ยังไม่ครอบคลุม:** เครื่องมือ OEM บนเครื่อง Dell/Lenovo/HP จริง (DRM-101/104/105), การติดตั้งไดรเวอร์จาก Windows Update จริง (VM ไม่มีรายการเสนอ),
pnputil กับแพ็กเกจไดรเวอร์จริง, จุดคืนค่าระบบ (DRM-103), รีสตาร์ทแล้วทำต่อ (DRM-102), การคลิก/ลากวางด้วยเมาส์จริงและ DPI สูง (DRM-117)

## แผนรอบถัดไป (เรียงตามความสำคัญ)

1. DRM-101/105: เก็บรายงานดิบจากเครื่อง Dell/HP จริงด้วยชุดดีบัก แล้วเขียนทดสอบจากไฟล์ตัวอย่าง
2. DRM-102/103: คู่มือและผลทดสอบบน VM Windows 11 สำหรับรีสตาร์ททำต่อและจุดคืนค่า
3. DRM-106: แคชระดับการรับรองของไดรเวอร์
4. DRM-107/108: SHA512 ของ .NET และลอง `winget source update` อัตโนมัติ
5. DRM-112/113: ปรับข้อตกลงคืนค่ารายการ + PSScriptAnalyzer ใน CI
6. ฟีเจอร์: ตรวจอัปเดตอัตโนมัติรายสัปดาห์ (Task Scheduler), ซ่อนอัปเดต Windows Update (DRM-114), ดาวน์โหลดเก็บไว้ติดตั้งแบบออฟไลน์
